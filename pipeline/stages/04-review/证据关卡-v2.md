# Hypit 复刻管线 v2 · 元认知复盘与证据关卡

> [!summary] 一句话
> 这次 ref105 复刻的问题，主要不是工具不够，而是 Claude 的**自我检查**出了偏差：先下结论后找证据、挑容易测的指标、为了快绕开 Hypit 的方法。v2 把 Hypit Skill 的方法整理成 **11 道关卡**，每道都写明"拿出什么证据才放行"，另加 8 条贯穿全程的元认知守则。
> 取代 [[Hypit 线 · 视频复刻工作流程 SOP]]（已废弃）。实测背景见 [[Hypit 线 · S01 按 Hypit 方法复刻（实测与评估）]]。

## 一、这次复盘怎么做的

- **材料**：2026-09-28 至 10-01 的整段会话记录（105 条用户消息），压缩成用户原话、Claude 输出和工具调用，按时间切成 4 段。
- **挖掘**：4 个 agent 各读一段，找 Claude 的每一次判断失误，每条都要附原文证据、背后机制、代价，以及能提前拦住它的关卡。
- **核对**：再用 4 个 agent 当怀疑者，逐条回原文核对，判为"确认 / 过度（真实但被夸大）/ 驳回"。
- **方法地图**：另 1 个 agent 通读 Hypit Skill（SKILL.md 和 17 篇参考文档），整理出逐关地图，并对照 S01 工程列出"Skill 里有、这次没用上"的指导。
- **结果**：71 条失误中 2 条被驳回；69 条成立，其中 44 条（62%）原描述有夸大，已按核对意见改写。

> [!important] 第一个元认知发现
> **连自我批评都会说过头。** 挖失误的 agent 有 62% 的条目被核对者判为夸大，比如把"晚了一步"写成"从没做"，把假设的后果写成已经发生。可见过度自信不只出现在报喜时，也出现在认错时。对策只有一个：**结论和核对分开，由独立的一方反驳式复查。**

## 三、五条元认知结论

1. **过度自信是主轴，而且会复发。** "说过头"最多（15 条），被纠正后又再犯（4-20）。原因是 Claude 倾向给出完成度高的答复，把"没有反例"当"已被证实"。这不能靠提醒自己改，要靠**结构**：每个结论必须标证据等级，"完成"类结论交给独立一方反驳式核对。
2. **知道不等于做到。** Hypit 的审片文档写明"按作用比对，不按像素比对；看运动要用连续帧"，Claude 读过（16:34）却没执行；"用中文回复"也写在压缩摘要里，照样没执行。规范必须变成**关卡清单**：嵌在流程里，出示证据才放行。
3. **路灯效应。** 验片查了切点、黑帧、像素均值这些容易测的，漏掉了真正决定质量的：镜内动作、镜间衔接、主角辨识度、色调。
4. **求快反而更慢更贵。** 10 次绕开 Hypit，每一次都在后面返工：没有 plan 报价，没法固定生成结果，也没有占位预览。按方法走的 S01 重做，结构层一次成型（13 个切点、字幕、原声都落在原帧），剩下的问题集中在素材本身。
5. **看不见的成本最危险。** 命令的副作用（提交、下载）和 token 成本平时都看不到。整个 S01，Claude 折算约 ¥178（$25.13 × 7.1），生成只花了 ¥1.45，相差约 120 倍。这些要主动去核实、去测量，才会进入决策。

## 四、管线 v2：11 道证据关卡

每一关的格式：做什么（Hypit 机制）→ **放行证据** → 费用 → 这次栽在哪。出处都来自 `~/.claude/skills/hypit/`。

### 第 0 关 立项与能力路线
- **做什么**：`hypit paths` 确认工程和 Profile；用 `hypit vocabulary @hypit/minimax-h3` 查清每类镜头需要哪种生成能力（参考图、参考视频、首尾帧、纯文本）；对照所选 Endpoint 支持什么。
- **放行证据**：一张"每类镜头 → 需要的输入 → 哪个服务能做"的对照表。其中的**质量与成本取舍**（市场 1088p 按秒计费、不收参考视频；自有 U17 收 1 段参考视频但只有 768P、按小时租机）由用户选定，并写进 BRIEF。
- **费用**：免费。
- **这次**：市场路线从一开始就锁死了"参考视频"这条路，动作复刻只能靠文字碰运气，而用户并不知道自己放弃了什么。

### 第 1 关 读参考片（ANALYSIS + TIMELINE）
- **做什么**：先粗扫整片，再对段落看密帧，关键处逐帧（`hypit media tile`、`tiles --every-frame`、`frames`、`boundaries`、`transcribe`）；关键动作用 `hypit media cut` 剪成证据片段。
- **放行证据**：TIMELINE 每镜写清内容、景别机位、**运动路径与速度（量化）**、入场出场和**转场手段**；关键动作有逐帧网格和剪出的片段；没证实的写"未确认"，**观察和解读分开写**。
- **费用**：免费，但读图会占上下文。
- **这次**：运动只写了"微动、跟拍、甩"这类名称，没量化；ANALYSIS 里"卡点证据不足（9/39，随机基线约 6.5）"，到 TIMELINE 和 TREATMENT 里却写成了"卡音乐拍"。

### 第 2 关 Brief（只有用户能定的事）
- **放行证据**：有用户原话、替换项、"没提到的按原片继承"、付费约定（账户、范围、接受的上限），以及**用户的工作偏好**（中文、令牌不经手、不自写替代工具）。
- **费用**：免费。

### 第 3 关 Treatment（导演的改编答案）
- **做什么**：先保住每个元素的作用，再重造它的形式。
- **放行证据**：ANALYSIS 列出的每个系统，在 Treatment 里都有明确去向，落到**"作用"一层**：继承、换一种形式完成、或明确放弃。每镜写清景别、机位、运动强度、**终点状态和转场**，并声明身份锚点。
- **费用**：免费。
- **这次**：原片"主角是冷调里唯一的饱和色"，这个作用没有传下去。主角黑袍、敌人也黑，远景里找不到主角。

### 第 4 关 素材导演设计（关键画面、生成关系、提示词）
- **做什么**：
  - 按镜头选生成关系：只需身份一致的，用参考图；终点画面本身就是设计的（比如倒握），用 `<h3:FrameVideo>` 首尾帧；动作节奏和运镜是看点的，把原片片段作为参考视频；
  - 先生成关键机位画面；
  - 每个请求只接它真正需要的参考图。
- **放行证据**：每镜有一张输入表；关键画面肉眼验收过；`hypit plan` 里没有"不支持"的请求。
- **费用**：设计免费，关键画面按张计费。
- **这次**：4 个请求都接同样的 4 张图，手部特写也接了刀客图；倒握只写在提示词里，所以一次都没演出来。

### 第 5 关 SVML 编写和免费占位预览
- **做什么**：13 个空 Segment、时钟、Trim/Retime、按原帧放置、画幅、字幕、声音，全部写成 SVML；用原片画面占位先预览一遍。
- **放行证据**：`hypit check` 通过；逐帧网格确认切点和字幕落在指定帧；preview 的 `hypit plan` 里付费请求为零。
- **费用**：免费。
- **这次**：做到了（46 个本机请求，0 个生成请求）。

### 第 6 关 估价与授权
- **放行证据**：`hypit plan` 只含预期的生成请求，且全部支持；`hypit pricing` 给出高峰和闲时区间，落在 Brief 的上限内；**模式、费率、范围任何一项变了，就重新报价、重新确认**；已识别的最大风险先用最小请求探过。
- **费用**：免费。

### 第 7 关 生成（Build）
- **做什么**：`hypit build … --follow`；等待时做下一关的免费工作。
- **放行证据**：Build 完成（或失败但已认出能复用的产出）；没有重复提交；轮询只查状态，间隔按任务时长定。
- **费用**：花钱。本次 4 个请求共 20 秒素材，¥1.00。

### 第 8 关 验收素材、选段、固定
- **做什么**：对**每条生成片**跑 `hypit media boundaries`，找出 H3 在片内自己切的镜头；用 `tiles --every-frame` 确认动作确实发生；用 `build-record` + `satisfy` 固定选中的结果。
- **放行证据**：每镜的选段都落在同一个内部镜头里；逐帧网格证明动作在选段内发生；assemble 的 `hypit plan` 里生成请求为零。
- **费用**：免费。
- **这次**：K 镜的选段跨过了 H3 的内部切点，多出两个跳切。

### 第 9 关 合成复审（按作用比对，看连续帧、带声音看）
- **做什么**：`hypit studio --run`（时间线加评论）；`hypit snapshot --step-frames 1`；对成片跑 `boundaries`，切点数应和原片一致；逐镜对照 TIMELINE 的"作用"列；能在合成层零成本修的先修（Recipe 的 brightness/contrast/saturation，组件的混合模式）。
- **放行证据**：
  - 每个切点前后有连续帧；
  - 成片切点数等于原片；
  - 逐镜判断"作用是否成立"，比如孤身、冲入人群、倒握打法；
  - 逐镜运动量和原片同量级；
  - 在 Studio 里带声音完整看过。
- **费用**：免费。
- **这次**：只比了静帧和像素均值，结果动作弱、跳切、甩镜缺失、色调偏灰都放过去了。

### 第 10 关 交付
- **放行证据**：完整看过、听过编码后的文件；结论分成"已达成 / 需要配置或再付费 / 受阻"；PROGRESS 如实列出没达成的，**不用"✅ 交付"盖住题眼的失败**；Build id 写进文件，下一个会话能接手。
- **费用**：免费。

## 五、贯穿全程的 8 条元认知守则

1. **每个结论标证据等级**：【实测】【推断】【未知】。推断不用"会、不会、一定"这类确定语气。
2. **"完成、通过、一致"要附证据路径**；对外交付前，由独立一方做一次反驳式核对。自我批评同样适用。
3. **花钱前三问**：plan 是否只有预期请求？这次生成能验证 BRIEF 的哪条硬约束、验证不了哪条？模式、费率、范围有没有变？另外，最大风险先用最小请求探。
4. **命令副作用先查清**：放进循环或脚本的命令，先看它**自己的** `--help` 或文档里写的副作用（会不会下载、提交，dry-run 是否生效）；查询只用只读接口。
5. **等待有节奏**：按任务时长定轮询间隔（市场任务 6–9 分钟，就每 2–3 分钟查一次状态），只在状态变化时汇报；等待期间做下一关的免费工作。
6. **一部片一个新会话**；阶段结论写进 BRIEF、TREATMENT、PROGRESS，靠文件交接。这次 Claude 折算费用中，76% 是反复读取缓存的长上下文。
7. **用户偏好写在 BRIEF 顶部**，每次汇报前自检：中文；令牌由用户自存、Claude 不经手；不写替代 Hypit 的脚本。
8. **自写脚本只补 Hypit 缺的能力**，写明补的是哪个缺口，并先问过用户。

## 八、技术原理（讲解片用）

- **Run、Build、Result**：Run 是这次要做什么的清单，Build 是按清单执行一次，Result 是这次的成品仓。每次执行都有据可查。
- **plan 和 pricing**：花钱前的账单预览，列出每个会发往外部的请求和价目，本身不花钱。
- **build-record + satisfy**：把满意的生成结果"钉住"；之后改剪辑、改字幕都不会重新生成，也不会重复花钱。
- **持久化 Build**：关掉终端，任务照样跑；失败时已完成的产出也能捡回来用。
- **时钟归一化**：不同来源的帧率、长度统一换算到同一个节目时钟（每秒 30 帧），才能逐帧拼接。
- **空 Segment 和 SemanticTake**：没有台词的镜头也是剧本里的一段，有自己的边界；字幕、特效挂在语义位置上，换了素材会跟着走。
- **按原帧放置**：切点本身就是设计时（快剪卡节奏），每个镜头直接放在原片的第几帧。
- **确定性剪辑和"请模型切镜"的区别**：在提示词里要求"这里切"只是请求；精确的剪切和变速要靠 Trim、Retime。
- **三种生成关系**：纯文本、首尾帧、参考（图或视频），各管一类镜头。
- **每种输入各负其责**：图管长相和环境，原片片段管动作节奏，提示词管态度和镜头。在提示词里描述一张图，不等于把这张图真的接给了模型。
- **四层分离**：模型、Provider、Endpoint、Profile 各管一层；服务做不到的请求在计划阶段直接报"不支持"，不会偷偷降级。
- **修问题修它的"主人"**：设计错改 Treatment，参数错改 Source 或 Recipe，选错素材改 Run；能在合成层修的，不靠重新生成。
- **文件就是记忆**：每个阶段的理解写进文件，换一个会话也能接着做。
