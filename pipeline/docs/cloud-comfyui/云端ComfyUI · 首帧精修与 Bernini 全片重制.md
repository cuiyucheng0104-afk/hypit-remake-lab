# 云端ComfyUI · 首帧精修与 Bernini 全片重制

> [!abstract] 结论
> 方法：**Qwen-Image-Edit 精修每个镜头的首帧 → Bernini 以精修帧为参考、以原片为底传播到整个镜头 → K01 给主角近景换脸 → 按切点拼回**。S01（13 个镜头）效果很好；推到全片后，79 个镜头里约 33 个换干净，13 个部分换好，27 个几乎没改，4 个用原片占位。根因是==Bernini 会照抄原片里醒目的外观（斗笠、浅蓝袍）==，排查了五种假设后确认这是模型行为而非参数问题。全片 v1 85.76 秒，全程自有算力、零平台费用。【实测】

## 1. 方法

```mermaid
flowchart LR
    A["原片按切点切镜头<br>末帧补齐到 4n+1"] --> B["取首帧"]
    B --> C["Qwen-Image-Edit 2511<br>图1=首帧 图2/3=角色参考"]
    C -->|人工挑选| D["定稿首帧"]
    A --> E["Bernini rv2v<br>source=原镜头<br>ref=定稿首帧 + 角色参考"]
    D --> E
    E --> F["K01 换头<br>（主角近景）"]
    F --> G["截回原长 → 按切点拼接"]
    E --> G
```

Bernini 的系统提示用「video editing on content propagation」（vi2v），指令：「图1是这个视频第一帧的编辑结果，把图1的修改传播到整个视频……动作、位置、机位、构图和节奏与原视频完全一致」。

## 2. S01（8.3 秒，13 个镜头）

### 2.1 切镜头

0.12 阈值得 15 个切点；逐一看首尾帧后，发现 #1–#3 其实是同一个镜头（雨滴闪光被误判），合并后 13 个（A–M），并按内容分为 hero / hench / both / hand 四类，每类配不同参考图和指令。

### 2.2 首帧精修：三版的教训

![[S01_首帧精修_三版对比.jpg]]
*每格三张：原首帧 / v1 / v2。*

| 版本 | 写法 | 结果 |
| --- | --- | --- |
| v1 | 场景图当图3 + 「背景替换为图3」 | C、E、G、L 构图保住；A、B、D、F、J、K、M 被改成对称回廊全景 |
| v2 | 场景改为文字描述 + 每镜头写明景别 | B、E、K 变好；特写仍被拉成中景 |
| local | **只换人，背景保持原建筑、只调成雨夜** | A、D、F、J 构图贴近原片 |

![[S01_首帧精修_只换人版.jpg]]

教训：只要指令里有「换背景」，Qwen 就倾向重画整幅；主角参考用「脸 + 三视图」设定图时会画出全身，特写要用脸部近景。最终选用：A D F I J M 用 local，B E G H K L 用 v2，C 用 v1。

### 2.3 传播与换脸

- Bernini 13 个镜头共约 38 分钟；构图、动作都对上（镜头 A 抽查：窗格墙、人物位置、景别与原片完全对齐）。
- 主角的脸被 Qwen 美化得偏年轻精致，与参考图的硬朗脸不同 → 用 **K01「单人换头」**（SAM3 追踪头部 + Wan Animate 只重画头部）：

![[S01_换脸_D.jpg]]
*参考脸 / 原片 / 换脸前 / 换脸后。换脸后脸型、胡茬、眼型、散落发丝都对上；小瑕疵是视线从平视变成略低头。*

- A、J 同样成功；M（多人打斗）第一次在 `torch.compile` 处卡死 30 分钟，用户决定不再重做。

![[S01_成片对照抽帧.jpg]]
*S01 成片对照（每格上原片、下重制）。*

## 3. S02–S09（77.5 秒，66 个镜头）

### 3.1 切分与分类

- 0.12 阈值在雨水闪光多的段落严重误切（S05 13 秒切出 45 段），全片 164 个候选；改用 0.3 阈值 + 短于 3 帧并入前一镜头 → **66 个**。代价：会漏掉部分真实切点。
- 人工分类（见 [[plan.json]]）：主角近景 12、头目 3（S02-3 的 14 秒嘶吼、S04-10 的 41 秒嘶喊、S08-8 头目被击倒）、只有刺客 17、手部/剑 5、主角 + 刺客 29。头目脸部参考从图片2 设定图裁出。

![[S02-S09_66镜头首帧.jpg]]

### 3.2 首帧：46 可用，20 失败

吸取 S01 教训，全部用 local 写法。66 张约 20 分钟。

![[S02-S09_首帧精修检查_1.jpg]]
![[S02-S09_首帧精修检查_2.jpg]]

失败的 20 张几乎都是**拖影、昏暗、抽象的首帧**：Qwen 没有可保留的构图，就编出一张站位合影（有的还凭空多出一个浅蓝袍人物）。这 20 个镜头改走「不用首帧，只按参考图改原片」（rv2v）。

### 3.3 批量运行

| 阶段 | 时间 | 说明 |
| --- | --- | --- |
| Bernini 66 段 | 00:35 → 04:19 | 无失败；每段约 3 分钟，S09-2（233 帧）最长 |
| 参考图版对照 7 段 | → 04:51 | S02-1/2/5/6、S03-2/6/8；比较后**全部不如首帧版**（袍子变回浅蓝或灰白、刺客斗笠消失、脸变成别人） |
| K01 换脸 12 段 | 04:51 → 05:13 | 全部成功；关掉编译后每段 1–2 分钟 |
| 拼接 | 05:13 | 2573 帧 / 85.76 秒，与原片逐帧对齐 |

后续阶段由 [[chain.sh]] 自动串起：等视频进程结束 → 换脸 → 拼接。

## 5. 为什么 Bernini 会「照抄原片」

S04-11 的定稿首帧是对的（主角无斗笠、刺客戴斗笠），成片却与原片几乎一模一样。逐一排除：

| 假设 | 检验 | 结论 |
| --- | --- | --- |
| 首帧与参考图重名被覆盖 | 核对服务器上 `S04-11.png` 的 md5 = 定稿首帧 | 否 |
| ComfyUI 重启后环境变了 | 原样重跑 S01-A，结果与之前完全一致；日志显示参考都已接入（2–4 路 context） | 否 |
| 场景描述太弱 | 换成 S01 的详细场景描述重跑 | 否，仍照抄 |
| 参考图与原片第 0 帧冲突 | 把原视频第 0 帧直接替换成定稿首帧 | 否，第 1 帧就回到原样 |
| 引导太弱（cfg=1） | cfg_chain（V1.25 I4.5 TI4.0） | 部分：第 1 帧换对，第 6、12 帧斗笠又回来 |

![[诊断_S04-11_首帧与成片.jpg]]
*左上原首帧、右上定稿首帧；下排成片第 0、8 帧——与原片无异。*

![[诊断_S04-11_cfg_chain.jpg]]
*cfg_chain：开头换对，越往后越回到原片外观。*

结论：原片中**醒目、持续出现**的外观特征，Bernini 单次编辑改不干净；这是模型的偏好，调参数只能缓解。

## 6. 提升方向

1. **先改原片，再编辑**：用 SAM3 抠出斗笠做内补去掉、把浅蓝袍按遮罩调成黑色，让「照抄原片」不再有害。预计能救回大部分「未改」镜头。【推测，待验证】
2. **切镜头要准**：TransNetV2 或 0.12 阈值 + 人工合并，消除镜头内漏切。
3. **首帧取最清楚的一帧**，每镜头 2–3 张候选再挑；模糊镜头不再让 Qwen 瞎编。
4. **自动质检 + 自动重跑**：视觉模型判断「斗笠 / 浅蓝袍」、人脸相似度判断身份，不合格的用 cfg_chain 重跑。
5. **收尾**：统一调色（部分镜头地面偏绿）、FlashVSR 超分到 1080p、所有主角可见镜头换脸，最后在 Hypit 里配字幕、音乐、音效。

## 7. 另一条路：按分镜用 H3 重新生成

用户问：只用 Hypit 反推提示词、H3 重新生成、再拼碎片，效果会怎样？分析：

| | 编辑原片（本篇） | H3 重新生成 |
| --- | --- | --- |
| 动作一比一 | 高：结构来自原片 | 低：按描述重拍，站位、出招、机位都会变 |
| 人物与场景 | 残留原片外观 | 100% 新设计，无原演员、无原片画面 |
| 画质 | 960×480，偶有偏暗偏糊 | 最清晰（T2 试验） |
| 短镜头 | 帧数随意 | H3 最短 4 秒、训练 5 秒以上，1 秒镜头要生成 4 秒再截 |
| 镜头间衔接 | 天然与原片一致 | 站位、方向、人数难前后一致 |

成片会是「按同一份分镜和剪辑节奏，重新拍的一场雨夜打斗」：切点与时长可以精确对齐（Hypit 拼装），每个动作不一样。若走这条路，建议用 **首尾帧**（Qwen 精修每个镜头的起止帧 → H3 FrameVideo；1 秒以下的镜头用 Wan2.2 首尾帧 G02/G15，不受 4 秒下限约束），比纯文字接近原片得多。用户可以提供 MiniMax 官方 API；密钥应写入本机文件而不是聊天，且云端可能拦截真人脸，只能喂精修后的 AI 角色帧。

建议下一步：拿 S02（7 个镜头、11.6 秒）做 A/B——A = 本篇流程 + 「先改原片」；B = 精修首尾帧 + H3 重生成。
