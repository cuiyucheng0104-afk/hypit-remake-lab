# 蓝V认证教程 · 复刻测试（前 30 秒）

参考片：`references/lanv-30s/`（解读 `ANALYSIS.md`，时间线 `TIMELINE.md`）。

## 目标

测试 Hypit 的能力：**换讲解员 + 重做包装**。

| 保留 | 重做 |
| --- | --- |
| 俯拍手机的操作画面（原片 2.13 s 以后） | 开场讲解员：tk人物形象 里的女生，H3 在自有服务器上生成，办公室中近景，口型对上开场白 |
| 操作段的原配音 | 标题：顶部色带 + 两行标题「#新的企业蓝V认证 / 如何认证？」 |
| | 字幕：底部色带，逐字点亮，与口播同步 |
| | 红色指引：9 个箭头 + 1 个红圈，全部挂在台词的词上（起止都由词决定） |

## 做法（全部在 Hypit 里）

- `lanv.svml`：一份 Source 写完整条片子；`presenter.svrun` 只生成讲解员，`lanv.svrun` 出成片。
- 讲解员：`h3:ReferenceVideo`，参考图 = 绿幕素材 9.5 s 那一帧，参考音 = 原片开场 2.2 s 的人声（给音色）。
- 两段表演各自用 WhisperX 对齐成 SemanticTake，拼成 Timeline；开场变长或变短，后面所有指引、字幕自动跟着移。
- 版式 720×1280：标题带 0–250，舞台 250–1050，字幕带 1050–1280。操作画面用放大的 Frame 取景（×2.395），
  原片烧进去的标题和字幕正好落在两条色带下面被盖住。
- 指引位置来自原片红色像素的逐帧测量（`references/lanv-30s/evidence/red-track.json`），由 `gen/pointers.py` 换算成画布坐标。

## 已知限制

- 原片的红箭头是烧在画面里的，去不掉；新箭头放在同一位置、画得更大，盖住大部分，但原箭头上下跳动时可能露出一点。
- 原片 30 s 处「提交」之后还有半句下一段的话，那一段做了静音。
- 所有生成和渲染都在本机 / 自有 GPU 上完成，不产生平台费用。

## 结果（2026-09-29）

- 成片：`out/lanv-remake-v2.mp4`（720×1280，30.7 s），Build `bld_20260929T113837439Z_FDCDC6D5EF`；桌面副本 `蓝V教程-Hypit复刻-30s.mp4`。
- 讲解员用第 3 次生成（`bld_20260929T112458931Z_0A0A8DD2A5`），在 `lanv.svrun` 里用 `<build-record>` + `<satisfy>` 固定，重跑不会重新生成。
  - v1（4 s）：台词没说完就结束；v2（5 s，要求「立刻开口」）：先胡说一句再说台词；v3（6 s，自然节奏）：0.39–2.75 s 完整说完，取 0.15–2.95 s。
- 改 `gen/pointers.py` 或 `gen/composition.svml.part` 后，用 `python3 gen/assemble.py 0.15s:2.8s` 重新生成 `lanv.svml`。

## 过程中发现的问题

- 自写 provider 的轮询有竞态：任务刚好在两次查询之间完成会被误判为「任务丢失」。已修（队列里没有时再查一次 history）。
- Hypit 0.2.16 渲染问题：media-track 单元写了 `exit` 动画、窗口又不是从 0 开始时，入场结束后单元就不见了。复现见 `probe/`；现在的指引不写 exit。
- typography 的 Paint 按书写顺序叠加，Shadow / Stroke 要写在 Fill 前面，否则把字盖成黑的。
